# One valid repair

Keep the draft, show a persistent plain-language error near the action/field, and offer retry. Announce status accessibly. Keep focus predictable and distinguish validation from network failure. Test keyboard operation and screen-reader labels as well as the visual state.

**How to check:** A native button supplies expected keyboard and accessibility semantics for an action.

Other repairs are acceptable if they satisfy the stated rule. Explain the failure timeline and show a relevant test. Code length and matching keywords are not evidence.
