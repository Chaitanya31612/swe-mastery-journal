# UX · Design for understanding

Beginner builds the model. Intermediate adds real constraints, failure cases, and tradeoffs. Follow the sequence below. Folder names and module IDs stay stable for saved progress.

## Beginner

- 01. [Start with the user’s task, not the screen](01-ux-task-model/README.md): Turn a vague feature request into a task, context, success condition, and recovery path.
- 02. [Perception, grouping, and information hierarchy](02-ux-hierarchy/README.md): Use proximity, similarity, alignment, and contrast to make the page’s structure understandable.
- 03. [Choice, memory, and progressive disclosure](03-ux-choices/README.md): Reduce decision effort while keeping useful options discoverable.
- 04. [Targets, pointing, touch, and motor effort](04-ux-targets/README.md): Design controls that are easy to reach and distinguish, beyond making icons larger.
- 05. [Accessibility as a foundation for usable interaction](07-ux-inclusive-access/README.md): Check semantics, names, focus, contrast, motion, and zoom as part of the main flow.

## Intermediate

- 06. [Feedback, errors, undo, and honest progress](05-ux-feedback/README.md): Design visible system state and recovery for slow, failed, and partially completed work.
- 07. [Forms, words, and decision-friendly defaults](06-ux-forms-content/README.md): Write labels, hints, validation, and empty states that help users act correctly.
- 08. [Research and metrics: replace confident guesses with evidence](08-ux-research/README.md): Plan a small usability study and interpret product metrics without confusing clicks with success.
- 09. [A repeatable UX review and redesign workshop](09-ux-review-capstone/README.md): Review a workflow using task evidence, interaction principles, accessibility, and measurable outcomes.
