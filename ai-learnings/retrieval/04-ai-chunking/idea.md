## Understand

Chunking divides content into retrievable units. A tiny chunk can lose the heading, exception, or table row that gives it meaning.

A huge chunk can include too much unrelated text, cost more, and crowd out other evidence. There is no universally best token size.

Start with the document's structure: section headings, paragraphs, lists, tables, code blocks, and references. Keep useful context such as a document title and section path.

Overlap can preserve boundary context but also duplicate evidence and inflate counts. Parent/child retrieval can search a smaller unit and return a larger supporting section.

Evaluate retrieval and answer support on questions that cross boundaries. Keep chunking version with the index.

Do not quietly combine exact counts from duplicated overlapping text; business aggregates still belong in authoritative code.
