# Git · Change with confidence

Beginner builds the model. Intermediate adds real constraints, failure cases, and tradeoffs. Follow the sequence below. Folder names and module IDs stay stable for saved progress.

## Beginner

- 01. [Commits, branches, and the three places](01-git-snapshots/README.md): Draw HEAD, the index, and the working tree before running a command.
- 02. [Small commits and precise diffs](02-git-staging/README.md): Separate changes with partial staging and verify exactly what a commit will contain.
- 03. [Merge, rebase, and conflict meaning](03-git-history/README.md): Choose a history operation from the graph and resolve intent rather than markers alone.
- 04. [Undo without guessing](04-git-recovery/README.md): Choose restore, reset, revert, or reflog from what must be preserved.
- 05. [Fetch, pull, and review a small change](05-git-collaboration/README.md): Explain remote-tracking refs and avoid treating fetch as a merge.

## Intermediate

- 06. [Find a regression with bisect and worktrees](06-git-investigation/README.md): Use evidence to locate a bad change while keeping active work intact.
- 07. [Cherry-pick, revert, and moving a fix deliberately](07-git-surgery/README.md): Move a small fix between release lines and distinguish patch replay from history preservation.
- 08. [Conflicts are behavior decisions](08-git-conflict-lab/README.md): Resolve a conflict by comparing base and both intents, then test the combined rule.
- 09. [Reflog, bisect, and exact-snapshot investigation](09-git-investigation-practice/README.md): Combine recovery and regression search without destroying unrelated working edits.
- 10. [A practical Git release and review routine](10-git-team-release/README.md): Review a change, integrate upstream work, and preserve a traceable release without rewriting shared history casually.
